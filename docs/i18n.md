# 国际化

插件文案分三处：

- `locale/*.json`：插件标题与描述。
- `rows/<子路径>/locale/*.json`：功能行的标题与描述。
- `src/client/locales.ts`：界面文案。

前两处由宿主在插件未激活时读取，第三处由浏览器渲染。

## 约束

- 用户可见文案 MUST 经前端字典或元数据资源提供：
  - 前端字典：`src/client/locales.ts`，由 `ctx.locale.register` 注册。
  - 元数据资源：`locale/<语言 id>.json` 与 `rows/<子路径>/locale/<语言 id>.json` 的 `meta`。
- 前端字典 MUST 同时提供 `zh` 与 `en`，两份键集 MUST 一致。
- `meta.title` 与 `meta.description` MUST 为每种基线语言各写一份，各文件的 `meta` 键集 MUST 一致。
- 英文标题与界面文字 MUST 使用 sentence case，只大写首词与专有名词。
- 元数据资源 MUST 在 `package.json` 的 `exports` 与 `files` 中声明。
- 译文 MUST 保留占位符、斜杠命令与 API 字段名的原文。
- locale 资源 MUST 不含零宽空格 U+200B 与 BOM U+FEFF。
- 文案与元数据的变更 MUST 由测试覆盖结构、键集与打包内容。

宿主按语言回退链读取这两处资源。缺一份基线语言或漏掉打包声明时，用户看到英文包名或键名。

## 元数据资源

| 文件 | 内容 |
| --- | --- |
| `locale/zh.json` | 中文标题与描述 |
| `locale/en.json` | 英文标题与描述 |

`meta` 字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `meta.title` | 是 | 插件行与详情页的标题，单行 |
| `meta.description` | 是 | 能力、用法与限制 |
| `meta.detail` | 否 | 详情页文档路径，指向包内 Markdown；省略时详情页使用 `README.md` |

宿主读取行为：

- 当前语言没有资源文件时，沿回退链取下一份，最终回落 `en`。
- 缺 `meta.title` 或 `meta.description` 时，回落 `package.json` 的 `name` 与 `description`。
- 插件停用状态下照常读取。

## 包清单声明

```json
{
  "exports": { "./locale/*.json": "./locale/*.json" },
  "files": ["dist", "cordis.patch.yml", "locale/*.json", "rows", "assets/*", "icon.svg", "README.md"]
}
```

漏掉 `exports` 时宿主读不到元数据；漏掉 `files` 时发布包缺文件。

## 行元数据

子路径行不读 `package.json`，宿主改读该子路径下的两个导出：

| 导出 | 指向 |
| --- | --- |
| `./<子路径>/locale/*.json` | `./rows/<子路径>/locale/*.json` |
| `./<子路径>/icon` | `./rows/<子路径>/icon.svg` |

- 子路径与 `cordis.patch.yml` 中 `name` 的后缀一致，例如 `sweeper`。
- `files` 包含 `rows`。
- 图标是 24×24 viewBox 的线框 SVG，带 `role="img"` 与英文 `<title>`，不超过 256 KiB。
- 缺少导出时，Plugins 页显示模块名与通用图标。

## 前端字典

- 命名空间为 `dsh-plugin-practical-tool-bundle`，字典在 `src/client/locales.ts`，中文字典是键集事实源。
- 官方功能开关的文案用 `officialFeatures.*` 前缀：
  - `feature.<id>` 是功能名：中文「自动化任务」「目标」「任务清单」「计划模式」「交付文件」，英文 `Schedule`、`Goal`、`Task list`、`Plan mode`、`Present files`。
  - `detail.<id>` 是关闭后果说明。
  - `error.*` 按路由错误码选择，未知值用 `error.unknown`。
- 路由失败回答的 `error` 是错误码，界面据此选文案；`message` 里的原始说明不显示。
- `apply` 里注册：`ctx.locale.register(NS, { zh, en })`。
- 槽位注册传 `locale: NS`，组件通过注入的 `t` 取文案。
- 槽位之外的文案用 `ctx.locale.bind(NS)`。
- 键名并入 `LocaleNamespaceMap`，缺失的键在编译期报错。

## 语言与回退

- 用户在 Settings → General → Language 选择语言，选择写入宿主设置并跨浏览器生效。
- 未选择时按浏览器语言匹配已注册语言，匹配失败回落 `en`。
- 查找顺序：当前语言 → 该命名空间 → `common` 命名空间 → 键名。
- 切换即时生效，`<html lang>` 同步更新；注册时捕获的文案保持注册时的语言。

## 新增一种语言

1. 复制 `locale/en.json` 为 `locale/<id>.json`，翻译 `meta.title` 与 `meta.description`。
2. 对 `rows/` 下每个子路径做同样的复制与翻译。
3. 语言 id 不在宿主内置集合内时，先由语言包调用 `ctx.locale.addLanguage({ id, label, fallback: 'en' })`。
4. 在 `src/client/locales.ts` 增加同键集字典，并加入注册调用。
5. 更新 `tests/metadata.test.ts` 的基线列表与 `tests/client-official-features.test.ts` 的字典断言。
6. 运行 `pnpm format && pnpm check`。

## 校验

| 命令 | 检查 |
| --- | --- |
| `pnpm vitest run tests/metadata.test.ts` | 包级与行级元数据的结构、键集、禁用字符、图标与清单声明 |
| `pnpm check` | 类型、lint、测试与构建 |
| `npm pack --dry-run --json` | 发布内容包含全部 `locale/*.json` |

实机核对：在 Plugins 页切换语言，核对本插件与六个功能行的标题、描述与图标随之变化，停用状态下照常显示。
