## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把模板转化为可安装的工具组合包 (Priority: P1)

维护者把当前插件模板改造成一个独立插件：插件标识、包名、文档与宪章都换成新插件自身的名称，模板示例实现全部移除，依赖对齐到最新的宿主版本，安装后“插件”页显示中文标题「dsh使用工具组合包」以及一行根行和五行功能行。

**Why this priority**: 其余功能都建立在这个插件身份上；没有完成转化，插件仍是模板示例。

**Independent Test**: 在空白 profile 中安装本插件，插件页出现「dsh使用工具组合包」及相关功能行，模板示例工具与示例行不再出现。

**Acceptance Scenarios**:

1. **Given** 插件已安装到一个干净的 profile，**When** 打开“插件”页，**Then** 显示「dsh使用工具组合包」以及清理会话、清理推理块、Claude 技能、重启按钮、手机触控放大五行。
2. **Given** 宿主语言为英文，**When** 再次打开“插件”页，**Then** 标题与描述显示对应的英文文案。
3. **Given** 模板的示例工具与示例前端行仍在仓库中，**When** 完成转化，**Then** 安装后的插件不再提供它们，仓库文档也不再以模板自称。

---

### User Story 2 - 在侧栏清理会话 (Priority: P1)

用户在侧栏底部点击扫帚按钮，看到当前可清理的会话数量，两次点击确认后执行清理：先把所有未置顶会话（含未分组的）归档，再永久删除全部已归档会话及其日志。正在打开或运行中的会话不会被中断。

**Why this priority**: 会话日志是本机磁盘占用的主要来源，这是最常用的功能。

**Independent Test**: 在有多条已归档与未置顶会话的 profile 中，点击扫帚并确认清理，面板报告归档与删除数量，侧栏与磁盘上对应会话消失。

**Acceptance Scenarios**:

1. **Given** 侧栏底部显示扫帚按钮，**When** 鼠标悬停，**Then** 按钮出现与重启按钮一致的悬停样式，仅强调色不同。
2. **Given** 会话分组已就绪，**When** 打开清理面板，**Then** 面板显示未置顶数量与已归档数量。
3. **Given** 面板已打开，**When** 第一次点击「清理」，**Then** 按钮进入确认态，窗口内第二次点击才执行。
4. **Given** 确认执行完成，**When** 查看结果行，**Then** 显示归档数、删除数、跳过数、延后数与失败数中的非零项。
5. **Given** 某个会话仍在主视图打开或仍在运行，**When** 执行清理，**Then** 该会话被跳过或延后，清理不中断它的对话。
6. **Given** 会话分组尚未加载完成，**When** 打开面板并尝试清理，**Then** 面板提示稍后再试，且不发出清理请求。

---

### User Story 3 - 从侧栏重启服务 (Priority: P2)

用户点击侧栏底部的重启按钮，在确认对话框确认后，当前服务或应用被重启，页面在服务恢复后自动刷新；重启期间显示进度，长时间未恢复时给出等待时间与手动刷新入口。

**Why this priority**: 修改插件与配置后需要重启宿主，桌面场景下手工重启困难。

**Independent Test**: 点击重启并确认，服务重新启动后页面自动刷新，且重启后服务进程标识与重启前不同。

**Acceptance Scenarios**:

1. **Given** 侧栏底部显示重启按钮，**When** 点击，**Then** 出现确认对话框，取消后不重启。
2. **Given** 用户确认重启，**When** 服务接受请求，**Then** 出现进度遮罩，服务恢复后页面自动刷新。
3. **Given** 重启耗时超过阈值，**When** 一直未恢复，**Then** 遮罩显示等待秒数与手动刷新按钮，轮询继续。
4. **Given** 页面运行在桌面应用内，**When** 确认重启，**Then** 整个应用关闭并自动重新打开，文案与网页场景区分。
5. **Given** 重启请求已被接受，**When** 重复触发重启，**Then** 后续请求被拒绝，不会拉起第二个进程。

---

### User Story 4 - 自动清理不被接受的推理块 (Priority: P3)

当模型服务以 400 拒绝历史消息中的推理块（签名属于另一段对话、加密内容无法解密），插件把模型可见历史里的推理块去掉后重试同一步，对话继续，日志与用户看到的内容保持原样。

**Why this priority**: 这是恢复能力，只在特定 provider 下触发，但触发时对话完全无法继续。

**Independent Test**: 用会拒绝历史推理块的 provider 继续一段含推理块的对话，该步自动重试并成功，日志中保留原始记录。

**Acceptance Scenarios**:

1. **Given** 历史中含推理块的对话被 provider 以该类 400 拒绝，**When** 插件介入，**Then** 同一步以去掉推理块的历史重试一次并继续。
2. **Given** 重试仍然失败，**When** 错误返回给用户，**Then** 不再无限重试，用户看到原始失败原因。
3. **Given** 插件未启用，**When** 出现同类拒绝，**Then** 行为与未安装插件一致。

---

### User Story 5 - 使用项目内的 Claude 技能 (Priority: P4)

会话工作目录所在项目（向上查找包含 `.git` 的目录）中 `.claude/skills` 下的技能并入该会话的技能目录，与 `.dsh/skills` 的技能并列；技能文件改动后目录自动刷新，插件只读不写。

**Why this priority**: 复用项目已有的 Claude Code 技能，不影响其他功能。

**Independent Test**: 在含 `.claude/skills/<name>/SKILL.md` 的项目里新建会话，技能列表出现该技能；修改文件后列表刷新；项目文件内容不变。

**Acceptance Scenarios**:

1. **Given** 项目含 `.claude/skills/<name>/SKILL.md`，**When** 在新会话中查看技能，**Then** 该技能可用并标明来源。
2. **Given** 会话工作目录是项目的子目录，**When** 查看技能，**Then** 仍能读到项目根下的技能。
3. **Given** 技能目录中的文件被修改，**When** 等待刷新窗口，**Then** 技能列表反映最新内容。

---

### User Story 6 - 手机端放大控件 (Priority: P5)

手机宽度（≤767px）下，会话列表、侧栏、顶栏与输入区的字号和控件被放大，便于触控；桌面宽度不受影响。

**Why this priority**: 只影响手机访问，属于体验增强。

**Independent Test**: 用手机宽度打开页面，控件明显放大；切回桌面宽度恢复原样。

**Acceptance Scenarios**:

1. **Given** 页面以手机宽度打开，**When** 加载完成，**Then** 会话列表与输入区控件的尺寸被放大。
2. **Given** 页面以桌面宽度打开，**When** 加载完成，**Then** 页面样式与未安装插件一致。
3. **Given** 手机通过远程配对访问页面，**When** 加载完成，**Then** 放大样式同样生效。

---

### User Story 7 - 单独开关各项功能 (Priority: P3)

用户可以在“插件”页单独停用五项功能中的任意一项，对应界面在下次状态刷新后消失，其余功能照常；重新启用后界面回来，不需要刷新页面。

**Why this priority**: 多行结构的意义就在这里；没有它，拆行只剩形式。

**Independent Test**: 停用重启按钮行，侧栏重启按钮在一个刷新周期内消失；重新启用后按钮回来，页面没有刷新。

**Acceptance Scenarios**:

1. **Given** 五项功能都已启用，**When** 停用清理会话行，**Then** 扫帚按钮消失，重启按钮与清理推理块能力保留。
2. **Given** 某行已停用，**When** 重新启用它，**Then** 对应界面在下一个刷新周期内恢复。
3. **Given** 某行停用，**When** 查看浏览器请求，**Then** 前端不再对该行发出重复的失败请求。

---

### Edge Cases

- 清理时用户取消第二次点击或移开面板：不执行任何删除。
- 清理请求返回失败：面板显示失败提示，会话与日志保持原状。
- 重启请求的连接被中断：只要旧进程确实退出，页面继续等待并在新进程就绪后刷新。
- 重启在桌面应用内失败（脚本宿主或资源管理器不可用）：对话框显示失败原因与日志路径。
- 推理块清理遇到无法识别的 400：不修改历史，按原错误返回。
- 项目没有 `.claude/skills`：技能目录保持原样，不报错。
- 技能目录尚不存在随后被创建：在探测窗口内被发现并生效。
- 手机样式表请求失败：页面保持原有尺寸，不阻塞其他功能。
- 根行被停用：整个前端下线，状态路由随之消失，页面不再发出相关请求。
- 状态路由不可用：前端保留当前界面，等下一次刷新周期再判断。

## Requirements *(mandatory)*

### Functional Requirements

**插件身份与仓库转化**

- **FR-001**: 插件 MUST 以包名 `dsh-plugin-practical-tool-bundle` 发布，中文标题为「dsh使用工具组合包」，并提供英文标题与两种语言的描述。
- **FR-002**: 安装到 profile 后，插件 MUST 在“插件”页显示 FR-001 的标题与描述；标题与描述 MUST 随宿主语言切换。
- **FR-003**: 插件 MUST 由一行根行与五行功能行组成：清理会话、清理推理块、Claude 技能、重启按钮、手机触控放大；每行 MUST 可在插件页单独停用。
- **FR-004**: 仓库 MUST 完成模板转化：README、宪章、`AGENTS.md` 与开发文档不再以模板自称；模板示例工具、示例前端行与示例配置 MUST 移除；历史 spec 与 changelog MUST 清空。
- **FR-005**: 全部 `@deepseek-ai/*` 依赖 MUST 对齐到 `0.2.2-rc.5`，并按仓库规则同步依赖安装白名单。
- **FR-006**: 插件 MUST 只提供 FR-003 列出的五项功能；定时任务、简洁模式预设与远程访问竖屏皮肤关闭 MUST NOT 进入插件。
- **FR-007**: 插件 MUST NOT 提供配置项；各行按源插件的默认行为运行。
- **FR-008**: 插件 MUST 携带 `icon.svg`，并在包清单中声明。

**前端装载与行开关**

- **FR-009**: 前端 MUST 由根行提供，五个功能行 MUST NOT 各自加载前端产物。
- **FR-010**: 根行 MUST 提供一条聚合状态路由，返回各功能行当前是否可用。
- **FR-011**: 前端 MUST 轮询该状态路由并据此挂载或卸载对应界面；停用的行 MUST NOT 引起反复的失败请求。
- **FR-012**: 状态路由不可用时，前端 MUST 保持当前界面，不因单次失败卸载功能。
- **FR-013**: 行开关引起的界面变化 MUST NOT 需要刷新页面。

**清理会话**

- **FR-014**: 侧栏底部 MUST 提供一个图标按钮打开清理面板，悬停样式 MUST 与同排的重启按钮结构一致，背景使用自身强调色的 12% 混合。
- **FR-015**: 面板 MUST 显示未置顶会话数与已归档会话数，并在会话分组未就绪时显示等待提示。
- **FR-016**: 清理 MUST 分两阶段执行：先归档全部未置顶会话（含未分组会话），再删除全部已归档会话的日志。
- **FR-017**: 执行清理 MUST 需要两次点击确认，第二次点击超出时间窗后重新进入未确认态。
- **FR-018**: 清理 MUST NOT 中断主视图正在查看的会话或正在运行的会话；这类会话 MUST 计入跳过或延后。
- **FR-019**: 清理完成后 MUST 报告归档、删除、跳过、延后与失败的数量，无失败时也 MUST 给出成功反馈。
- **FR-020**: 清理请求失败 MUST 以错误提示呈现，且不删除任何会话。

**重启按钮**

- **FR-021**: 侧栏底部 MUST 提供重启按钮，点击后 MUST 先出现确认对话框。
- **FR-022**: 确认后 MUST 重启运行中的服务；网页场景重启服务进程，桌面场景重启整个应用并在完成后自动回到页面。
- **FR-023**: 重启期间 MUST 显示进度遮罩；超过阈值仍无响应时 MUST 显示已等待时间与手动刷新入口，并继续轮询。
- **FR-024**: 同一进程内 MUST 拒绝重复的重启请求，避免启动第二个实例。
- **FR-025**: 重启失败时 MUST 显示失败原因与日志路径，并允许重试。

**清理推理块**

- **FR-026**: 当 provider 以 400 拒绝历史推理块时，插件 MUST 从模型可见历史中移除推理块后重试同一步，且只重试一次。
- **FR-027**: 该处理 MUST 只改变模型可见历史；会话日志与用户看到的对话记录 MUST 保持不变。
- **FR-028**: 其他类型的请求错误 MUST 不触发该处理。

**Claude 技能**

- **FR-029**: 插件 MUST 把会话工作目录所在项目（向上查找 `.git`）中 `.claude/skills` 下的技能并入技能目录。
- **FR-030**: 技能来源 MUST 只读，MUST NOT 写入、移动或转换项目文件。
- **FR-031**: 技能目录中文件变化后 MUST 自动刷新会话可见的技能列表；目录尚不存在时 MUST 按探测间隔重试。
- **FR-032**: 同名技能 MUST 按固定优先级合并，来源名称 MUST 固定为 `claude`。

**手机触控放大**

- **FR-033**: 插件 MUST 为 ≤767px 宽度提供放大会话列表、侧栏、顶栏与输入区控件的样式，桌面宽度 MUST 不受影响。
- **FR-034**: 手机端 MUST 通过可用的加载路径取得该样式：本地页面走样式表链接，远程配对页面走带认证的请求。

**路由命名**

- **FR-035**: 插件全部 HTTP 路由 MUST 位于 `dsh-practical-tools` 命名空间下，MUST NOT 与宿主中其他插件的路由冲突。

**模板与质量约束**

- **FR-036**: 代码变更 MUST 同步更新 `tests/`，发布内容 MUST 由包内容测试回归。
- **FR-037**: 用户可见行为 MUST 记录在 `README.md`；机制与风险变化 MUST 更新对应文档。
- **FR-038**: 发布设置 MUST 启用：版本号为 `1.0.0`，CI 的 publish job 在打 tag 时运行。

### Key Entities

- **插件行**：profile 中的安装单位，包含标识、配置与启用状态；根行与功能行共享包名。
- **行状态**：各功能行当前是否可用，由聚合状态路由返回。
- **会话**：一段对话及其日志目录，具有置顶、归档与运行状态。
- **已归档集合**：全局记录哪些会话已归档；清理删除日志后仍保留条目。
- **重启进程代次**：每次启动的进程标识与启动时间，用于判断新实例是否就绪。
- **技能来源**：技能目录及其显示名称与优先级。
- **手机样式表**：仅在手机宽度生效的样式文本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在干净 profile 中安装后，插件页显示「dsh使用工具组合包」与五行功能行；切换语言后标题与描述为对应语言，且不出现模板示例。
- **SC-002**: 侧栏底部依次出现清理与重启两个按钮；两者悬停态的背景混合比例、尺寸与圆角一致。
- **SC-003**: 在含 10 条未置顶会话与若干已归档会话的 profile 中执行一次清理，面板报告的数量之和与实际归档和删除数量一致，且无失败项。
- **SC-004**: 主视图打开的会话在清理后仍可继续对话。
- **SC-005**: 网页场景重启后页面在服务恢复后 10 秒内自动刷新；桌面场景应用重新打开后页面可用。
- **SC-006**: 含推理块的对话遇到该类 400 后，同一步在 1 次重试内继续，日志条数不变。
- **SC-007**: 含 `.claude/skills` 的项目中，新会话在 5 秒内能看到该技能；修改技能文件后 5 秒内列表反映更新。
- **SC-008**: 767px 宽度下受影响的控件尺寸大于未安装插件的同一页面；768px 以上无差异。

- **SC-010**: `pnpm check` 与 `pnpm build` 全部通过，发布包只含运行所需的文件。

## Assumptions

- 插件只用于本机 profile，用户已安装 0.2.2-rc.5 或更新版本的宿主。
- 会话日志位于宿主默认数据目录下，插件不改变该位置。
- 手机样式依赖宿主既有的 767px 断点约定。
- 项目技能以 `SKILL.md` 形式存在，格式与 Claude Code 一致。
- 五项功能的行为与源插件一致，源插件源码作为行为参照；默认值沿用源插件。
- 根行能在宿主侧读到各功能行的启用状态。
- 与宿主中其他插件并存时互不冲突。
- npm 发布由用户在新仓库配置 Trusted Publisher 后生效。
