# 实机测试报告：SA 会话区分远程消息与本机消息

**日期**：2026-11-23
**宿主**：0.2.2-rc.5（全局 dsh）
**profile**：`rdt-032-sa-presence`，隔离 `DSH_HOME`、会话与存储
**模型**：mock provider；宿主、插件、会话存储与 GUI 为真实实现

## 范围

本报告验证程序机制：预设作用域、`agent/pre-step` 提醒与包装、GUI 显示与真实输入链路。回复渠道、`send_report` 首行注明等模型行为需要真实模型与飞书，按 [quickstart.md](./quickstart.md) 场景 1–3、5–7 由用户验收。

| 用例 | 结果 | 关键断言 |

## 后端机制

驱动脚本在真实宿主中创建 `SA-任务会话`、`SA-调度会话` 与 standard 会话，用 `agent.steer` 投递各来源消息，读取会话事件断言。

| 用例 | 结果 | 关键断言 |
| --- | --- | --- |
| W1 meta-tools 消息包装 | 通过 | 普通文本与 `<system-reminder>` 文本都包进 `<dispatch_session_message>`，开标签只出现一次 |
| W2 本机消息不包装 | 通过 | `source.kind: user` 的原文不变，任务会话无调度状态提醒 |
| D1 本机消息触发 local 提醒 | 通过 | 提醒在本机消息之前；连续第二条本机消息不重复提醒 |
| D2 飞书切回 remote、上报不触发 | 通过 | local 与 remote 各一条提醒；`lark-super-agent` 上报不新增提醒 |
| D3 桥接提醒不改变状态 | 通过 | `reminder: true` 的桥接提醒不触发状态提醒 |
| D4 standard 预设不受影响 | 通过 | standard 会话无 `sa-dispatch-presence` 提醒与包装 |

## GUI

无头 Chrome 打开隔离 GUI，会话经 `workspaceId` 注册后出现在会话列表。

| 用例 | 结果 | 关键断言 |
| --- | --- | --- |
| G1 来源标记显示 | 通过 | meta-tools 消息显示为「收到执行请求」卡片，展开后可见完整 `<dispatch_session_message>` 块；首条任务只显示一次 |
| G2 GUI 本机输入 | 通过 | 在调度会话输入框发送本机消息成功 |
| G3 GUI 输入触发状态切换 | 通过 | 该会话的状态提醒依次为本机、飞书、GUI 本机三条，最后一条为 local |

## 发现

- `sessionController.create` 不接受 `title`，会话标题由首条本机消息生成；测试会话用 `workspaceId` 创建才会出现在 GUI 会话列表。
- meta-tools 来源的消息在 GUI 中折叠为「收到执行请求」卡片，来源标记默认不占界面空间。
- 运行时被释放时未完成的回合在 GUI 显示为已停止；不影响提醒与包装的持久化结果。
