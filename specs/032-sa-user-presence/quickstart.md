# Quickstart: SA 会话区分远程消息与本机消息

## 前置条件

- 本机安装 DSH，插件按 [README](../../README.md) 安装。
- `dsh-plugin-lark-bridge` 已配置调度工作区，桥接会话预设为 `SA-调度会话`。
- 至少登记一个工作区，飞书鉴权有效。

## 自动检查

```sh
pnpm format && pnpm check
pnpm build
```

预期：类型检查、lint、`tests/sa-worker.test.ts`、`tests/sa-dispatch.test.ts` 与产物测试通过。

## 实机验收

### 场景 1：调度会话识别本机消息

1. 从飞书发一条任务，确认飞书收到回执。
2. 在 Web GUI 的调度会话输入一个问题。

预期：回复出现在正文，飞书无新通知。

### 场景 2：在电脑前时的上报转达

1. 场景 1 之后，等待工作会话上报。

预期：调度会话在正文转达，飞书无新通知。

### 场景 3：飞书消息恢复远程

1. 从飞书再发一条消息。
2. 等待下一份上报。

预期：回复与转达都经飞书送达。

### 场景 4：首条任务带来源标记

1. 让调度会话新建一个工作会话。
2. 打开该工作会话查看首条消息。

预期：

- 首条消息包在 `<dispatch_session_message>` 中，GUI 显示正常，无重复消息。
- 工作会话经 `send_report` 交流。

### 场景 5：工作会话本机对话

1. 在工作会话直接输入一个问题。

预期：答复出现在该会话正文，调度会话未收到对应上报。

### 场景 6：本机模式上报

1. 在工作会话直接修改一项需求。

预期：调度会话收到上报，`text` 首行为 `用户在电脑前`。

### 场景 7：调度消息恢复远程模式

1. 从飞书补充一条要求，调度会话转给该工作会话。

预期：该消息带 `<dispatch_session_message>`，工作会话改为经 `send_report` 交流。

### 场景 8：状态提醒不重复

1. 在调度会话连续发送两条本机消息。
2. 再发送一条飞书消息。

预期：

- 第一条本机消息前出现「at the computer」系统提醒，第二条前没有新提醒。
- 飞书消息前出现「remote」系统提醒。
- 期间到达的工作会话上报不触发新提醒。

## 已知限制

- 回复渠道由真实模型执行，单元测试只验证提醒逻辑、包装逻辑与规则文本。
