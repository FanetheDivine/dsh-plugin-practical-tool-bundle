- [D-007] Q: 读不到视图持有信息或会话快照时如何处理？ -> A: 按无打开会话继续清理。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开中的会话不被清理 (Priority: P1)

用户在侧栏底部点击扫帚并确认清理时，正在显示的会话保持原样。会话仍在原视图、仍可继续对话，日志保留在磁盘上。

清理的最终目的是删除日志。DSH 没有原生删除，所以清理先归档未置顶会话，再删除已归档会话的日志。归档是必经步骤。

**Why this priority**: 清理不可恢复。归档正在显示的会话会把主视图切到新对话，直接中断用户工作。

**Independent Test**: 在准备好的配置中打开一个会话，执行一次清理，检查该会话未被归档、日志目录存在、主视图仍停留在该会话。

**Acceptance Scenarios**:

1. **Given** 主对话区打开着会话 A，**When** 用户确认清理，**Then** A 不被归档、不被删除，日志目录保留。
2. **Given** 主对话区打开着会话 A 并切到轨迹页签，**When** 用户确认清理，**Then** A 同样不被归档、不被删除。
3. **Given** 主对话区打开着会话 A 并切到插件提供的 GIT 页签，**When** 用户确认清理，**Then** A 同样不被归档、不被删除。
4. **Given** 子代理聊天面板显示着会话 S，**When** 用户确认清理，**Then** S 不被归档、不被删除。
5. **Given** 会话 A 只在左侧列表出现，没有被任何内容视图打开，**When** 用户确认清理，**Then** A 按既有规则归档并删除。

---

### User Story 2 - 打开 subagent 时保护祖先会话 (Priority: P2)

用户打开一个 subagent 会话时，清理不归档、不删除它的全部祖先会话。子会话与父级引用保持完整。

**Why this priority**: 祖先会话被清理会让打开中的 subagent 失去上下文与来源，也会破坏会话树。

**Independent Test**: 打开一个 subagent 会话，执行清理，检查每个祖先会话日志目录存在，父子关系仍可解析。

**Acceptance Scenarios**:

1. **Given** 打开了 subagent 会话 C，其父会话 P 未置顶且未归档，**When** 用户确认清理，**Then** P 不被归档、不被删除。
2. **Given** 打开了 subagent 会话 C，其父会话 P 已归档，**When** 用户确认清理，**Then** P 保持归档，日志保留。
3. **Given** 打开了 subagent 会话 C，且 C 的父会话本身也是 subagent，**When** 用户确认清理，**Then** 整条祖先链都被保护。
4. **Given** 打开了 subagent 会话 C，**When** 用户确认清理，**Then** 其他未打开的会话仍按既有规则归档与删除。

---

### Edge Cases

- 同一会话在主对话区与子代理聊天面板同时显示。
- 主对话区在对话、轨迹与插件页签之间切换。
- 打开的会话不在左侧列表快照中，例如刚打开、列表尚未刷新。
- 打开的 subagent 的祖先会话位于另一个工作区。
- 祖先会话正在运行或正在等待用户回答。
- 会话列表快照不可用。
- 页面刷新后重新打开会话，再执行清理。
- 宿主重启后，已归档会话在用户打开前被清理。
- 同一会话在另一个客户端打开。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 清理 MUST 保留主对话区正在显示的会话：不归档，不删除日志。对话、轨迹与插件页签都属于主对话区。
- **FR-002**: 清理 MUST 保留子代理聊天面板正在显示的会话。
- **FR-003**: 打开中的会话是 subagent 时，清理 MUST 同样保留它。
- **FR-004**: 清理 MUST 保留打开中 subagent 的全部祖先会话：不归档，不删除日志。
- **FR-005**: 被保护的祖先会话已归档时，清理 MUST 保持其归档状态并保留日志。
- **FR-006**: 保护的判定 MUST 读取界面提供的会话持有信息，不依赖会话是否出现在左侧列表。
- **FR-007**: 仅出现在左侧列表、未在任何内容视图打开的未置顶会话 MUST 按既有规则归档并删除。
- **FR-008**: 工作区快照未就绪时，清理 MUST 拒绝执行并说明原因。
- **FR-009**: 会话持有信息或会话列表不可用时，清理 MUST 按无打开会话继续执行。
- **FR-010**: 面板的未置顶计数 MUST 扣除受保护会话，只显示本次实际会清理的数量。
- **FR-011**: 清理结果 MUST 沿用「跳过 {n} 个打开中的会话」一行，受保护会话计入该计数。
- **FR-012**: 清理结果 MUST 不新增其他保护数量文案。
- **FR-013**: 除受保护会话外，清理 MUST 保持既有的归档与删除行为。

### Key Entities

- **会话**：一段对话及其日志目录，具有置顶、归档、运行与打开状态。
- **视图持有**：主对话区或子代理聊天面板正在显示某个会话，可能有多处同时持有。
- **主对话区页签**：对话、轨迹与插件页签，共享同一个会话。
- **祖先链**：subagent 会话沿父级引用直到根会话的链，可跨工作区。
- **清理请求**：一次先归档、后删除日志的操作，包含待处理会话、保护集合与结果计数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在主对话区任意页签打开会话后执行清理，该会话被归档或删除的次数为 0。
- **SC-002**: 打开 subagent 后执行清理，其祖先链中被归档或删除的会话数为 0。
- **SC-003**: 仅在左侧列表出现的未置顶会话仍被归档并删除。
- **SC-004**: 已归档的被保护祖先会话在清理后归档状态不变，日志目录存在。
- **SC-005**: 面板的未置顶计数等于未置顶会话数扣除受保护会话后的数量。
- **SC-006**: 连续执行两次清理，第二次的归档与删除数量为 0。

## Assumptions

- 清理通过先归档、再删除日志实现，归档是删除的必经步骤。
- 界面持有信息只覆盖当前客户端。
- 祖先关系可从会话列表的父级引用取得。
- 清理的两步确认交互保持不变。
- 置顶与运行中规则保持不变。
- 会话 id 可以安全用作目录名，日志目录布局为 `<会话根>/<目录键>/<会话 id>`。
