# 快速验证：清理会话的保护范围

## 前置

- 在检出根目录安装依赖：`pnpm install`。
- 构建产物：`pnpm build`。

## 单元与产物检查

```sh
pnpm check
pnpm build
```

预期：类型检查、lint、`code` 与 `dist` 两个测试 project 全部通过。

## 场景 1：主对话区打开的会话

1. 在一次性 profile 中打开一个会话，保持主对话区显示该会话。
2. 点击侧栏底部的扫帚，再点两次「清理」。
3. 预期：会话仍在主对话区，未被归档；`<DSH home>/sessions/<目录键>/<会话 id>` 存在；结果行不含「已删除」。
4. 切换到轨迹或插件页签后重复第 2 步，结果相同。

## 场景 2：子代理聊天面板

1. 打开一个 subagent 聊天面板。
2. 执行清理。
3. 预期：面板显示的 subagent 与它的全部祖先会话都未被归档，日志目录存在。

## 场景 3：仅列表中的会话

1. 保留一个未置顶、未打开、未归档的普通会话。
2. 执行清理。
3. 预期：该会话被归档；刷新页面后侧栏不再显示它；日志目录被删除或计入延后。

## 场景 4：计数

1. 打开一个会话，记录面板的未置顶计数。
2. 执行清理。
3. 预期：面板计数已扣除打开的会话；结果行的跳过数包含受保护会话。

## 失败排查

- 保护未生效：检查浏览器控制台的清理请求体，确认 `keepIds` 含打开会话与祖先。
- 保护集合为空：确认 `sessions` 服务可用，且会话行带有 `mainView` 或 `sidebarChat` 持有计数。
- 删除仍发生：确认宿主在归档前记录了内存会话，删除阶段把它们计入 `deferred`。
