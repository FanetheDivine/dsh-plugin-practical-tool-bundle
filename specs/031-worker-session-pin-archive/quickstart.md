# Quickstart: 调度会话置顶与归档工作会话

## 前置条件

- 本机安装 DSH，插件按 [README](../../README.md) 安装。
- `dsh-plugin-lark-bridge` 已配置调度工作区，桥接会话预设为 `SA-调度会话`。
- 至少登记一个工作区，并能向该工作区分派任务。
- 真实模型可用；置顶与归档由调度会话按提示词执行。

## 自动检查

```sh
pnpm format && pnpm check
pnpm build
```

预期：

- `pnpm check` 类型检查、lint 与 `tests/sa-dispatch.test.ts` 全部通过。
- `pnpm build` 重新生成 `dist/sa-dispatch.mjs`，产物测试通过。

## 手动验收

### 场景 1：新建会话置顶

1. 在调度会话发送一项需要新建工作会话的任务。
2. 等调度会话回执目标工作区与会话。

预期：

- 新建的工作会话出现在会话列表置顶区。
- 原有置顶会话仍在其后，相对顺序不变。
- 任务要求已送到该会话。

### 场景 2：复用会话不置顶

1. 在调度会话发起同类任务，选择复用候选会话。
2. 观察该会话的置顶状态。

预期：

- 候选会话保持原置顶状态。
- 复用未改变其他会话的顺序。

### 场景 3：任务完成归档

1. 等任务完成，调度会话把状态改为完成。
2. 查看常规会话列表与归档列表。

预期：

- 该任务的工作会话离开常规列表，出现在归档列表。
- 任务笔记与上报同时归档。
- 恢复该会话后回到原工作区分组，且未置顶。

### 场景 4：共用会话保持未归档

1. 让两个未完成任务使用同一个工作会话。
2. 完成其中一个任务。

预期：

- 该会话仍在常规列表。
- 完成另一个任务后，该会话进入归档。

### 场景 5：失败报告

1. 构造归档失败的场景，例如先手动归档目标会话后再让任务完成。

预期：

- 任务仍标记为完成。
- 调度会话在同一轮回复里说明归档失败。
- 其他会话照常归档。

## 已知限制

- 提示词遵循度由真实模型决定，单元测试只验证规则文本存在。
- 共用会话检查读取归档前的任务笔记；检查与归档之间新建任务引用时存在竞态。
