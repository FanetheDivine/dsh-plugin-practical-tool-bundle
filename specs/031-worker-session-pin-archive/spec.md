# Feature Specification: 调度会话置顶与归档工作会话

**Feature Branch**: `feat/031-worker-session-pin-archive`

**Created**: 2026-11-23

**Status**: Approved

**Input**: User description: "要求调度会话 在新建work会话后 将其置顶；任务完成后 将其归档"

## Open Decisions

无。全部决策已确认，记录见 Clarifications。

## Clarifications

### Session 2026-11-23

- [D-001] Q: 哪些工作会话需要置顶？ -> A: 只置顶调度新建的工作会话；复用的候选会话保持原置顶状态。
- [D-002] Q: 置顶与归档由谁执行？ -> A: 调度会话按提示词执行；程序不自动补做。
- [D-003] Q: 一个工作会话同时服务多个任务时，某任务完成是否归档该会话？ -> A: 先读未完成任务笔记，仍被引用就保持未归档。
- [D-004] Q: 任务标记完成时工作会话仍在运行，如何处理？ -> A: 归档请求同时停止其运行工作，会话立即进入归档。
- [D-005] Q: 置顶失败时如何派发任务？ -> A: 不阻断派发，在同一轮回复里向用户说明失败。
- [D-006] Q: 用户手动置顶的工作会话随任务完成归档时，置顶如何处理？ -> A: 随归档移除置顶；恢复后保持未置顶。
- [D-007] Q: 工作会话归档失败时，任务完成与失败说明如何处理？ -> A: 仍把任务标记完成，并单独报告归档失败。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新建工作会话自动置顶 (Priority: P1)

调度会话接到新任务并新建工作会话后，该会话立即出现在会话列表的置顶区，用户一眼看到任务由哪个会话执行。

**Why this priority**: 置顶直接决定新任务的可见性。没有置顶时，用户要在全部会话中寻找刚创建的会话。

**Independent Test**: 在调度会话发起一项需要新建会话的任务，确认新会话位于列表顶部且带置顶标记，原有置顶会话的相对顺序不变。

**Acceptance Scenarios**:

1. **Given** 调度会话在已登记工作区决定新建工作会话，**When** 会话创建成功，**Then** 该会话已置顶，并排在全部未置顶会话之前。
2. **Given** 会话列表已有其他置顶会话，**When** 新建会话完成置顶，**Then** 新建会话位于这些会话之前，它们的相对顺序不变。
3. **Given** 新建会话置顶失败，**When** 任务继续派发，**Then** 用户收到失败说明，任务照常发给该会话。

---

### User Story 2 - 任务完成后归档工作会话 (Priority: P1)

任务完成后，该任务使用的工作会话离开常规会话列表，用户不再需要为已完成任务保留会话位置。

**Why this priority**: 常规列表只留当前工作。归档保留恢复能力，同时避免已完成任务的会话长期堆叠。

**Independent Test**: 把一个任务改为完成，确认该任务的工作会话离开常规列表、可从归档恢复，任务笔记与上报照旧归档。

**Acceptance Scenarios**:

1. **Given** 任务使用的工作会话空闲，**When** 调度会话把任务状态改为完成，**Then** 这些工作会话进入归档，常规列表不再显示。
2. **Given** 工作会话已归档，**When** 用户从归档恢复该会话，**Then** 会话回到原工作区分组，并保持未置顶。
3. **Given** 任务状态改为失败或等待用户，**When** 状态写入成功，**Then** 对应工作会话保持未归档。

---

### User Story 3 - 复用会话与共用会话的边界 (Priority: P2)

调度会话复用已有候选会话执行任务时，置顶与归档只改变本次任务需要改变的状态，不破坏用户手动整理的列表。

**Why this priority**: 会话复用是默认路径。每次复用都置顶或归档会打断用户对其他会话的安排。

**Independent Test**: 复用已置顶与未置顶的候选会话各一次，再让两个任务共用一个会话；确认置顶状态不变，共用会话在两个任务都完成前保持未归档。

**Acceptance Scenarios**:

1. **Given** 候选会话已被用户置顶，**When** 调度会话复用它执行新任务，**Then** 该会话保持置顶。
2. **Given** 候选会话未置顶，**When** 调度会话复用它执行新任务，**Then** 该会话保持未置顶。
3. **Given** 一个工作会话同时服务未完成任务与本次完成任务，**When** 本次任务归档，**Then** 该会话保持未归档。
4. **Given** 用户手动置顶的会话只服务本次完成任务，**When** 任务归档该会话，**Then** 会话进入归档且置顶移除。

---

### Edge Cases

- 新建会话后立即置顶时，会话尚未写入持久化或工作区注册表不可用：置顶失败，派发继续，用户收到说明。
- 会话已被用户手动置顶：重复置顶不改变置顶顺序。
- 会话已归档：置顶请求失败；该会话不作为新建任务的目标。
- 会话已被删除或工作区注册表不认识该会话：归档跳过该会话，其余会话照常归档。
- 任务完成时工作会话正在运行：归档请求先停止其运行工作，再完成归档。
- 同一任务被重复标记完成：归档保持幂等，已归档会话不重复写入。
- 用户恢复已完成任务的会话：会话回到常规列表，任务记录保持已归档，会话不自动重新置顶。
- 归档过程中某个会话失败：其余会话仍完成归档，用户收到失败说明。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 调度会话 MUST 在已登记工作区新建工作会话成功后立即置顶该会话。
- **FR-002**: 置顶 MUST 在向该会话发送任务要求之前完成。
- **FR-003**: 新建会话 MUST 排在全部未置顶会话之前；其他置顶会话的相对顺序 MUST 保持不变。
- **FR-004**: 复用的候选会话 MUST 保持原有置顶状态。
- **FR-005**: 置顶失败 MUST NOT 阻断任务派发；调度会话 MUST 在同一轮回复里向用户说明失败。
- **FR-006**: 任务完成时，调度会话 MUST 归档该任务记录的全部工作会话。
- **FR-007**: 归档 MUST 把会话移出常规列表；会话日志、目录与上报记录 MUST 保留。
- **FR-008**: 归档 MUST 移除该会话的置顶状态。
- **FR-009**: 归档前，调度会话 MUST 检查未完成任务笔记；工作会话仍被未完成任务引用时 MUST 保持未归档。
- **FR-010**: 工作会话仍在运行时，归档 MUST 停止其运行工作并完成归档。
- **FR-011**: 任务状态为进行中、等待用户或失败时，MUST NOT 触发工作会话归档。
- **FR-012**: 归档失败 MUST NOT 阻止调度会话把任务标记完成；调度会话 MUST 单独报告失败。
- **FR-013**: 用户 MUST 能从归档恢复工作会话；恢复后的会话 MUST 保持未置顶并回到原工作区分组。
- **FR-014**: 归档与恢复 MUST NOT 删除会话日志、会话目录或上报记录。

### Key Entities *(include if feature involves data)*

- **工作会话**：由调度会话新建或复用的执行会话，带置顶状态、归档状态与所属任务引用。
- **置顶集合**：会话列表中排在未置顶会话之前的会话顺序。
- **归档集合**：从常规列表隐藏、可恢复的会话集合。
- **任务**：带状态与工作会话 id 的记录；完成时触发工作会话归档。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新建工作会话在收到首条任务要求前完成置顶的比例为 100%。
- **SC-002**: 任务独占的工作会话在任务完成后的同一轮处理内全部归档，常规列表残留为 0。
- **SC-003**: 与其他未完成任务共用的工作会话在归档后保持可见的比例为 100%。
- **SC-004**: 置顶或归档失败时，用户在同一轮回复内收到失败说明的比例为 100%。
- **SC-005**: 恢复归档会话后，会话日志、目录与上报记录完整率为 100%。

## Assumptions

- 任务记录保存该任务使用的全部工作会话 id。
- 调度预设已启用会话置顶与归档能力。
- 归档表示从常规列表隐藏并可恢复，不删除日志。
- 调度会话新建工作会话时使用 SA-任务会话预设。
- 置顶与归档由调度会话按提示词执行，程序不自动补做。
- 用户可以在会话列表手动置顶会话，也可以从归档恢复会话。
- 一个任务可以对应多个工作会话。
- 任务完成时先归档任务笔记与上报，工作会话归档属于同一完成动作。
